# UI flows

How a user completes each important task. One section per flow. Take screens and steps from the real application or the approved design, never from imagination. Write `Unknown, verify` where unconfirmed. Link to the design file instead of describing visuals.

## Flow: <name the user goal>

- Who: the user role.
- Entry point: where the user starts.
- Design reference: link to the design file or frame.

### Steps

1. Screen or route, and what the user does.
2. Next screen or route, and what changes.

### States

- Loading: what the user sees.
- Empty: what the user sees.
- Error: what the user sees and how to recover.

### Exit

Where the user ends up, and what has changed in the system.
